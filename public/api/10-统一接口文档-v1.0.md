## 1. 全局约定

### 1.1 基础地址

| 域 | 地址 | 说明 |
|---|---|---|
| 内容（第三方） | `https://api.salesmarto.com/app-api/drama` | 6 个 GET，无鉴权 |
| 自研业务 | `https://api.cinecoin.app/v1` | 全部需 Bearer token（游客为匿名 token） |
| 广告回调（S2S） | `https://api.cinecoin.app/v1/ad/s2s/reward` | 只有广告平台服务端调用，**客户端不可达** |
| 后台 | `https://admin.cinecoin.app/api/admin` | 管理员会话 + 权限 + 审计 |

### 1.2 统一响应包

```json
{ "code": 0, "message": "ok", "data": {}, "request_id": "req_01HQ..." }
```

- `code = 0` 成功；非 0 见 [17. 错误码](#17-错误码与降级矩阵)。
- 第三方内容接口是 `{"code":200,"msg":"操作成功","data":{}}`，**两套包不同，适配层必须转换**，不要把 `200` 直接当业务码混用。
- 所有响应带 `request_id`，客户端日志与后台审计用它串链路。

### 1.3 鉴权

```
Authorization: Bearer <token>
X-Device-Id: <device_id>        // 安装级 UUID，卸载重装变更
X-App-Version: 1.0.3 (103)
X-Region: BR                    // 客户端上报，服务端以 SIM/GeoIP 为准，不一致时以服务端为准
```

- 游客态：冷启后 `POST /v1/auth/anonymous` 换匿名 token（TTL 30 天，静默续期）。
- 登录后换发正式 token，账本按 `MERGE` 类型并入余额（`ref_id = session_id`）。
- 幂等键作用域见 `OPEN-12`：游客与登录账号合并期的 `episode+user` 幂等键是否跨端生效，未定前按「合并后取并集，任一已计币则不再计」。

### 1.4 幂等、重试、超时

| 接口 | 幂等键 | 超时 | 失败降级 |
|---|---|---|---|
| `POST /v1/watch/heartbeat` | `play_id + seq` | 2s | 本地排队（<3 条）恢复后补发 |
| `GET /v1/feed` | — | 3s | 读本地缓存，展示离线态 |
| `POST /v1/ad/s2s/reward` | `trans_id` | 3s | 回查 3 次（1s/3s/10s）→ 仍失败落 DENIED，不预发不补发 |
| `GET /v1/wallet` | — | 2s | 上次缓存 + 「更新中」角标 |
| `POST /v1/withdraw` | `withdraw_id` | 5s | **不自动重试**（防重复扣款），提示「已提交」 |
| `GET /v1/withdraw/{id}` | — | 3s | 最后已知状态 + 时间戳 |
| `POST /v1/task/claim` | `task_id + date` | 2s | 按钮回弹，提示重试 |
| `POST /v1/events/batch` | 每条 `event_id` | 5s | 本地保留非敏感事件，恢复后补报 |

**写接口一律不自动重试**，只允许用户手动重试；重试必须复用同一幂等键。

### 1.5 金额与币值

- 账本字段 `delta` / `balance` 全部为 **integer 币**，永远不用浮点。
- 展示金额由服务端计算下发：`display = { coins, amount: "R$ 0,50", currency: "BRL" }`。**客户端不得自行做币→现金换算**（汇率是发布常量，但仍然只允许服务端算，避免两处口径）。
- 折算公式：`amount_brl = coins / 10000`（10.000 moedas = R$ 1,00）；`amount_usd = coins / 50000`（fx 5,00）。
- 四档提现：50.000 / 100.000 / 300.000 / 500.000 moedas = R$ 5 / 10 / 30 / 50，SLA 15 / ~18 / ~24 / ~30 个工作日。

### 1.6 分页

`page`（1 起）+ `size`（默认 20，上限 50），返回：

```json
{ "items": [], "page": 1, "size": 20, "total": 101, "has_more": true }
```

## 2. 接口分层与调用关系

```
┌─ 内容层（第三方，只读）───────────────────────────────┐
│ /home /categories /dramas /dramas/{id} /episodes /home-feed │
└──────────────┬──────────────────────────────────────┘
               │ 直连 or BFF 适配（见 3.6）
┌──────────────▼──────────────────────────────────────┐
│ 客户端（AdModule / WalletModule 互不 import）          │
│  ConfigCache · StrategyManager · PopupManager · EventTracker │
└──────────────┬──────────────────────────────────────┘
               │ /v1/*
┌──────────────▼──────────────────────────────────────┐
│ 业务层：Strategy · UserState · Frequency · Experiment │
│         Reward · Wallet/Ledger · AdEvent · Event      │
└──────────────┬──────────────────────────────────────┘
               │ 可信回调 / 定时对账
     TopOn 广告回调        PIX 打款回调
```

三条不可跨越的边界（PRD 5.11）：

1. 广告 → `ad_events` → Ledger → 提现，**箭头只能向右**；提现域不读 `ad_events`、广告域不同步调提现接口。
2. 频控中心是**唯一裁决者**，客户端不许本地计数后自行展示。
3. 客户端上报的是**播放器状态**，不是「已观看时长」；计币只认服务端计时。

### 3.3 三条实测结论（实现必须按这个来）

1. **分集接口不返回播放地址**。`videoUrl` 只出现在 `/home-feed` 的条目里，且实测 31 条只覆盖 12/101 部剧。
   → 取源必须三级回退，并如实标注来源级别：
   ```
   videoFor(dramaId, epNo) →
     exact  本剧该集有源（items 里 drama.id 与 episode.episodeNo 同时命中）
     drama  本剧任意集有源 → 复用该集视频（只用于演示，不参与计币）
     demo   全局首条视频（仅用于 UI 走查）
     none   无源 → 展示封面 + 「Conteúdo indisponível」，绝不假装在播
   ```
   **只有 `exact` 才允许提交 `watch/heartbeat` 计币**，`drama` / `demo` 的播放进度不上报计币（否则等于给不存在的集发钱）。
2. **响应不带 CORS 头**（无 `Access-Control-Allow-Origin`）。浏览器原型无法直连；原生客户端不受 CORS 限制，但**仍需 BFF 代理**（见 3.6），原因有三：鉴权与签名、授权字段过滤（`license_region` / `license_expire`）、播放地址防盗链。
3. **`/play` 路径实测 404，可用的是 `play_720p.mp4`**。任何「按 ID 拼 URL」的写法都会失败，只能读接口返回值。

### 3.4 与 PRD 5.15 契约的差异（必须登记）

PRD 5.15 写的是 `/v1/series`、`/v1/series/{id}/episodes`、`/v1/play/{episode_id}`（返回 m3u8 + token + 30min 过期）。上游实际提供的是 6 个只读 GET + mp4 直链。差异清单：

| 差异项 | PRD 期望 | 上游实际 | 处理 |
|---|---|---|---|
| 播放格式 | m3u8 + token | mp4 直链 | v1 用 mp4；BFF 保留 `play` 接口形状，返回 `url` + `expires_at`，内部实现换 CDN 签名 |
| 播放授权 | `token` + `expires_at` ≤30min | 无 token，地址长期有效 | BFF 加签名并设 30min 过期，为后续防盗链留位 |
| 授权过滤 | `license_region` / `license_expire` 缺则过滤 | 字段不存在 | 暂不过滤，**登记为合规待确认项（OPEN-16）**：无授权字段即无法证明分发权，BFF 需补白名单 |
| 缓存时长 | series 24h / detail 6h / episodes 6h | 接口无 cache header | BFF 侧按 PRD 时长缓存 |
| 计数字段 | `ep_count` | `totalEpisodes` | BFF 映射 |
| 搜索 | 未定义 | `/dramas?keyword=` | BFF 透传并做重音归一（NFD 去重音，葡语必需） |

### 3.5 字段映射（上游 → 客户端内部）

| 上游 | 内部 | 规则 |
|---|---|---|
| `id` | `api_id`（+ 展示用 `id = "r"+id`） | 数字与字符串都要能用 |
| `title` | `title` / `raw_title` | 剥离 `(Dublagem)` 类前缀，原名留 `raw_title` |
| `categoryCodes` | `genres[]` | `split(',')` + trim + 去空 |
| `totalEpisodes` | `ep_count` | ≤0 时兜底 1 |
| `freeEpisodeCount` | `free_count` | 缺省 0 |
| `heatText` | `heat_label` | 空则回落 `heatScore` |
| `coverUrl` | `cover` | `<img>` 必须带 `onerror` 隐藏，露出底层剪影，不许出现破图 |

### 3.6 BFF 适配层（推荐方案）

```
GET /v1/series?region=BR&page=1&size=20&genre=&keyword=
GET /v1/series/{id}
GET /v1/series/{id}/episodes
GET /v1/play/{episode_id}
```

- 内部转调上游 6 个接口，对外输出 PRD 5.15 的字段形状（`id/title/cover_3x4/genres[]/ep_count`）。
- 鉴权：`Authorization: Bearer <session>` + `X-Sign = HMAC-SHA256(app_key + ts + nonce)`，`ts` 偏差 >300s 拒绝。
- 缓存：series 24h、detail 6h、episodes 6h、play 不缓存。
- 降级：上游 5xx/超时 → 本地缓存库（可播可计币）→ 缓存也没有 → 空态 `Conteúdo indisponível` + 重试，**不进空白 Feed**。
- 原型阶段已实现「构建期快照 + 运行时探测」：`tools/snapshot.py` 抓取 → `data/snapshot.json`（115KB）→ 内嵌 `#cc-snap` → `CCData.reload()` 成功才切实时。这是无 CORS 环境下唯一可行的取数方式，可平移到 App 的首次启动兜底。

## 4. 配置下发接口

配置是「运营可改」的那一半；决策是「运行时算」的那一半。两者都用**单调递增 version**，客户端只按 version 覆盖缓存，不回落到旧版。

### 4.1 `GET /v1/config?scope=ad,invite`

```json
{
  "code": 0,
  "data": {
    "version": 42,
    "effective_at": 1762905600000,
    "values": {
      "ad.reward.daily_cap": 15,
      "ad.interstitial.daily_cap": 12,
      "ad.appopen.hourly_cap": 1,
      "ad.appopen.daily_cap": 1,
      "invite.settle_max": 50,
      "ad.total.hard_cap": 40
    }
  }
}
```

整包校验（**坏一条拒全包**，不允许部分生效）：

| 规则 | 违反处理 |
|---|---|
| 各 key 在合法区间内 | 整包拒绝，沿用上一版，5min 内告警 |
| `reward + interstitial + appopen ≤ hard_cap` | 整包拒绝，后台提示冲突项 |
| `hard_cap ∈ [30,60]` | 整包拒绝（防止调到 999 变相关掉风控） |
| 下发层级：国家 / app_version / 渠道 / 用户分层 | 同一用户同一时刻只命中一份 |

客户端兜底顺序：**接口 → 磁盘缓存 → 内置默认（15/12/1/1/50）**，默认值集中在一个 `ConfigDefaults` 对象里，禁止散落在业务分支。

生效与清零：日上限类**次日 00:00 BRT 生效**且**不清零当日已用次数**；开屏小时级与邀请名额立即生效。

### 4.2 `GET /v1/region-config`

```json
{
  "code": 0,
  "data": {
    "region_code": "BR",
    "currency": "BRL",
    "fx": 5.00,
    "content_source_id": "src_br_01",
    "withdraw_page_set": ["wp_br_a", "wp_br_b"],

```

- `fx` 是**发布常量**：接口里有这个字段只为透传给展示层，后台**不提供修改入口**。
- `min_payout_coins` 与账本口径一致，**不允许在此包内改**（本节只读）。
- 国家判定：SIM 的 MCC（免权限）→ 服务端 GeoIP → 系统 Locale → `default_region`，逐级回落，任一步命中即停。
- 检出 VPN：**不切区域，只打标** `region.vpn=1` 随首报送风控，提现走加强 KYC。

### 4.3 `GET /v1/popup-set?set=br_default`

```json
{
  "code": 0,

    "popup_set": "br_default",
```

校验（整包）：`priority` 0–100；`group` 白名单；`trigger.type` 限 6 种（`timer` / `app_open` / `wallet_enter` / `withdraw_fail` / `episode_completed` / `click`）；`limits.per_session ≤5`；`template` 必须是**客户端已内置**的模板 id（不下发任意布局，防配置错=白屏）。

**8 个弹窗真值表（服务端唯一来源，改动即配置）**

| popup_id | 触发器 | 优先级 | 互斥组 | 默认频控 | 需求 |
|---|---|---|---|---|---|
| onb_promise | app_open | 100 | onboarding | max_lifetime=1 | BF-01-08 |

| wheel | timer(30) | 70 | engage | per_session=3 · cooldown=180s | MZ-11-01 |
| notify_push | wheel_close(3rd) | 60 | engage | cooldown=7d | MZ-11-05 |
| checkin_nudge | app_open | 40 | engage | per_day=1，20:00 后 | BF-07-01 |

调度规则：同刻取优先级最高的一条，其余入队（队列上限 3，超出丢最低并记 `popup_dropped`）；同互斥组同刻只出一个；`ad_pre` 是用户主动触发的确认层，不排队不被丢弃，但「广告播放中不弹」优先。

### 4.4 `GET /v1/withdraw-page?exp=wd_page_v1`

```json
{ "code": 0, "data": { "page_id": "wp_br_b", "bucket": 78, "expires_at": 1765497600000 } }
```

- `bucket = hash(device_id + exp_id) % 100`，**服务端算并下发 `page_id`**；客户端不本地随机（否则同一用户会看到两套金额解释不了的页）。
- 同一设备 30 天内不换桶；实验结束自动回落默认面。
- 两面**只差呈现**，金额/门槛/汇率/SLA/拒绝原因码/KYC 要素必须**逐字一致**（自测按字符串 diff=0 校验）。

### 4.5 `GET /v1/bootstrap`（冷启聚合，推荐）

冷启如果按 4.1–4.4 + `/me` + `/wallet` + `/tasks` 逐个发，是 **7 个请求**，弱网下首屏会明显变慢。实际工程一定要做聚合：

```
GET /v1/bootstrap?app_version=1.0.3&scope=all
If-None-Match: "b_42_1762900000"
```

```json
{ "code": 0, "data": {
  "etag": "b_43_1762905600000",
  "server_time": 1762905600000,
  "config": { "version": 43, "values": { "ad.reward.daily_cap": 15, "invite.settle_max": 50 } },
  "region": { "region_code": "BR", "currency": "BRL", "fx": 5.00, "min_payout_coins": 5000 },
  "popup_set": { "set_id": "br_default", "version": 7, "items": [] },
  "withdraw_page": { "bucket": 78, "page_id": "wp_br_b" },
  "me": { "user_id": 1000123, "is_guest": true, "segments": ["new_user"] },
  "wallet": { "available_balance": 3200, "display": { "available": "R$ 3,20" } },
  "tasks": { "checkin": { "streak": 3, "today_claimed": false }, "claimable": 1 },
  "unread": { "withdraw_in_progress": 0, "gift_pending": 0 }
} }
```

规则：

- **一次请求拿到首屏需要的全部状态**；`scope` 可按需裁剪（`scope=config,region` 用于非冷启的局部刷新）。
- 支持 `ETag` + `If-None-Match`，未变更返回 **304**（body 为空），省流量也省电量。
- 各子对象与独立接口**字段完全一致**，客户端复用同一套解析器；聚合接口不能有私有字段。
- 任一子块失败**不影响其他子块**：失败块返回 `null` 并在 `errors` 里给 `{ "config": "50001" }`，客户端对该块走本地缓存兜底，不整包失败。
- `/wallet` 允许在 `bootstrap` 里带缓存值（`stale: true`），但**提现页必须重新拉 8.1 的实时值**，不能用冷启快照做资金操作。

## 5. 登录与用户信息接口

登录只有两条入口：**先游客、后可选 Google 绑定**。不做手机号、不做邮箱密码（BR 市场短信成本高且与网赚场景不匹配，`OPEN-20` 保留判断）。

```
冷启 ──▶ POST /v1/auth/anonymous（必有，换匿名 token）
              │
              ├─ 用户不登录 ──▶ 全功能可用，但**不可提现**（40301）
              │
              └─ 用户点「Entrar com Google」──▶ POST /v1/auth/google
                        │
                        ├─ 新账号 ──▶ 换正式 token，游客余额 MERGE 并入
                        └─ 已存在 ──▶ 换正式 token，两账本按规则合并
```

**为什么先游客**：安装即用、零门槛进内容，是这类 App 的核心转化设计；把登录墙放在提现前，符合「先给价值再要身份」。

### 5.1 `POST /v1/auth/anonymous`（游客登录）

冷启第一次请求，**不需要任何已有 token**。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `device_id` | string | 是 | 安装级 UUID，卸载重装会变；服务端按它做设备维度频控与防刷 |
| `app_id` | string | 是 | `cinecoin_br`（多 APP 预留，不写死） |
| `app_version` | string | 是 | `1.0.3 (103)` |
| `os` / `os_version` | string | 是 | `android` / `16` |
| `region` | string | 否 | 客户端上报；服务端以 SIM + GeoIP 为准，冲突时用服务端值并在响应回传 |
| `media_source` | string | 否 | 归因来源（`organic` / `facebook` / `googleadwords`…），首启由 MMP SDK 给 |
| `install_id` | string | 否 | 归因归因 ID，与 `device_id` 分开，便于卸载重装重归因 |

```json
// req
{ "device_id": "9f2c41a7-...", "app_id": "cinecoin_br", "app_version": "1.0.3 (103)",
  "os": "android", "os_version": "16", "region": "BR", "media_source": "organic" }

// resp
{ "code": 0, "data": {
  "user_id": 1000123,
  "token": "eyJhbGciOi...",
  "expires_at": 1765497600000,
  "refresh_token": "rt_7f3c...",
  "is_guest": true,
  "region": "BR",
  "server_time": 1762905000000,
  "new_user": true
} }
```

| 响应字段 | 说明 |
|---|---|
| `token` | Bearer token，**TTL 30 天**，到期前 7 天客户端静默续期（5.3） |
| `refresh_token` | 换 token 用，TTL 90 天，只存 Keystore，不进日志 |
| `is_guest` | `true` = 游客，提现被拦 |
| `new_user` | `true` 表示本次是新建，客户端据此走新人礼包 / 首开承诺链 |
| `server_time` | 服务端时间戳，客户端用它校正本地时钟（提现倒计时、签到日界都依赖） |

规则：

- **同一 `device_id` 重复调用返回同一个 `user_id`**（幂等），不新建账号、不重置进度；只有 token 会刷新。
- `device_id` 已绑定 Google 账号时，仍返回该账号的 `user_id` 且 `is_guest=false`，客户端直接进已登录态（不需要重新点 Google）。
- 服务端以 `device_id` 做**单设备单账号**约束（BF-08-01：1 设备 1 账号），同设备换号登录视为新账号，不与旧账号共享余额与邀请关系。
- 失败不阻塞启动：拿不到 token 时客户端进「受限模式」——可播缓存内容、不计数、不请求广告。

### 5.2 `POST /v1/auth/google`（Google 登录 / 绑定）

```json
// req
{ "id_token": "eyJhbGciOi...", "device_id": "9f2c41a7-...", "nonce": "n_8f21c" }
```

| 字段 | 说明 |
|---|---|
| `id_token` | Google Sign-In 返回的 **ID Token（JWT）**，不是 access_token；Android 端用 `GoogleSignIn` + `requestIdToken(webClientId)` 取 |
| `device_id` | 必须与游客 token 的 `device_id` 一致，服务端据此找到待合并的游客账本 |
| `nonce` | 客户端生成、参与 Google 签名的 nonce，服务端校验防重放 |

**服务端校验顺序（一条不过就拒，不回部分成功）**

1. 用 Google 公钥验签（JWKS，缓存 24h）；
2. `aud` 必须等于本项目 Web Client ID，`iss ∈ {accounts.google.com, https://accounts.google.com}`；
3. `exp` 未过期、`iat` 与服务端时间差 ≤300s；
4. `nonce` 与本次会话一致且未被使用过（Redis 5min 去重）；
5. 取 `sub` 作为 Google 账号主键（**不用 email**，email 可变）。

```json
// resp（新账号 / 首次绑定）
{ "code": 0, "data": {
  "user_id": 1000123, "token": "eyJ...", "refresh_token": "rt_...",
  "expires_at": 1765497600000, "is_guest": false,
  "merged": true,
  "merge": { "guest_balance": 3200, "merged_coins": 3200, "skipped": false },
  "account": { "nickname": "Maria S.", "email_masked": "m***@gmail.com", "avatar_url": "https://..." }
} }
```

| 分支 | 返回 | 客户端动作 |
|---|---|---|
| 游客首次绑定（常见） | `merged=true`，`merge_*` 有值 | 提示「Saldo transferido」，刷新 `/wallet` |
| 已有账号、本次设备无游客余额 | `merged=false` | 直接进已登录态 |
| 已有账号、本设备也有游客余额 | `merged=true`，两账本合并 | 同首绑 |
| `id_token` 无效/过期/`aud` 不符 | `40110 GOOGLE_TOKEN_INVALID` | 留在游客态，提示重试，**不清本地数据** |
| Google `sub` 已绑到别的 `device_id` 且该设备仍活跃 | `40911 ACCOUNT_BOUND_OTHER_DEVICE` | 提示「Conta já vinculada a outro aparelho」，给客服入口 |
| 用户取消 Google 授权 | 客户端不发请求 | 静默留在游客态，下次可再点 |

**账本合并规则（合并只做一次，写 `MERGE` 流水）**

- `delta = guest_balance`，`ref_id = session_id`，`idempotency_key = merge:{user_id}:{device_id}` —— 同一设备重复登录不重复合并。
- 只合并 `SETTLED` 余额；游客态下的 `PENDING`（首开承诺 200.000 未转正）**随之迁移但保留原到期条件**，不因登录提前转正。
- 解除解锁记录与追剧列表一并迁移（`user_unlock` / `favorites` 按 `device_id` 复制到正式 `user_id`）。
- 邀请关系**不合并**：游客态绑定过的邀请码随账号保留，但同一 `device_id` 上的第二个账号不得再绑（BF-08-01 反刷）。

### 5.3 `POST /v1/auth/refresh`

```json
// req
{ "refresh_token": "rt_7f3c...", "device_id": "9f2c41a7-..." }
// resp
{ "code": 0, "data": { "token": "eyJ...", "expires_at": 1768089600000, "refresh_token": "rt_9a11..." } }
```

- `refresh_token` **轮换**：每次刷新返回新值，旧的立即失效（防截获重放）。
- `40101` token 失效时客户端先走这里；刷新也失败 → 重新 anonymous（游客）/ 引导重新 Google 登录（已登录）。
- 已登录账号刷新失败**不得静默降级为游客**，否则余额会「消失」，必须明确提示重新登录。

| `invite_code` | 6 位邀请码（BF-08-01） | 服务端生成、终身不变；`/v1/invite/info` 会再返回一次带分享文案的版本 |
| `language` | 当前界面语言 | 只影响文案，不影响币种 |
| `kyc` | 提现前置状态 | `pix_bound=false` 时提现按钮置灰（BF-06-03） |
| `notification` | 通知权限引导（BF-09-04） | 拒绝后 7 天冷却由服务端记，客户端不重复弹 |
| `segments` | 服务端算好的分层 | 客户端只读不传，禁止用本地规则覆盖 |

**余额绝不出现在这里** —— `/v1/me` 只放身份与行为状态，钱只从 `/v1/wallet`（8.1）读。这是防止「两处余额不一致」的硬约束。

### 5.5 `POST /v1/auth/logout`

```json
{ "code": 0, "data": { "logged_out": true } }
```

- 撤销当前 `refresh_token`，清服务端会话；客户端清 token 后**立即重新 anonymous**，回到游客态进内容。
- 退出登录**不删除**账本与解锁记录（重登回到原账号）。
- 游客退出 = 清本地 token，下次冷启生成新 `user_id`（余额随之清空，需二次确认弹窗，`OPEN-21`）。

## 6. 观看与计币接口

### 6.1 `POST /v1/watch/heartbeat`

```json
{ "play_id": "p_7f21", "episode_id": 2001, "series_id": 1001, "position_ms": 45000, "state": "PLAYING", "speed": 1.0, "seq": 3 }
```

服务端算法（唯一计币依据）：

```
segment = (play_id, 连续心跳窗口)
Δt = 相邻心跳的服务端接收时间差        // 客户端时间戳不可信
Δp = position 增量（异常跳变 → 本段计 0 并重建基线）
有效时长 += min(Δt, Δp / speed)
有效覆盖 = 合理播放区间的去重并集长度
发币条件：有效时长 ≥ 90s 且 有效覆盖/总时长 ≥ 60%，同 episode 终身 1 次
```

| 参数 | 取值 | 说明 |
|---|---|---|
| 心跳间隔 | 15s | 前台播放才上报 |
| 状态变化补报 | 立即 | 暂停 / 退出 / 切集发末次位置 |
| 最小有效时长 | 90s | 60–89s 的剧按实际时长 ×100% 计 |
| 中断判定 | 切后台 >5s | 本段作废，从 0 计时（不累加） |
| 倍速 | >1.5× 不计 | 1.0–1.5× 正常 |
| 静音 | 仍计 | 但必须前台且画面在播 |
| 单集计币 | 1 次 | 终身 |
| 每日计币集数 | 40 集 | 超出仍可看，不再计币并提示 |
| 发放值 | 50 币/集（新剧首集 300） | 写死，不可配 |

响应：

```json
{ "code": 0, "data": { "credited": true, "coins": 50, "balance": 3200, "segment_ms": 91000, "covered_ratio": 0.62, "ledger_id": "A7F2", "segment_reset": false } }
```

> 客户端**不得**上报「已观看时长」，只报播放器状态；服务端自己算。这一条决定了「一次请求伪造 90 秒」不可能成功。

### 6.2 `GET /v1/feed?limit=12&cursor=`

服务端聚合内容接口 + 播放源，返回客户端可直接渲染的 Feed：

```json
{
  "code": 0,
  "data": {
    "items": [
      {
        "slide_id": "r1001_ep1",
        "series": { "id": "r1001", "title": "O Herdeiro", "cover": "https://...", "ep_count": 62, "heat_label": "12,3 mil" },
        "episode": { "id": 2001, "no": 1, "duration": 96, "free": true, "locked": false },
        "play": { "url": "https://video.../play_720p.mp4", "source": "exact", "expires_at": 1762909200000 },
        "rewarded_unlock": false
      }
    ],
    "next_cursor": "c_100"
  }
}
```

`play.source` 三值（`exact` / `drama` / `demo`）与 3.3 一一对应。`source != exact` 时客户端仍可播，但**不上报 heartbeat 计币**，并在调试面板显示来源级别。

### 6.3 解锁（广告解锁内容）

用户点锁定集时先取一个「解锁报价」，看完激励后由服务端核销：

```
POST /v1/unlock/quote   { "episode_id": 2005 }  → { quote_id, episode_id, ad_unit, expires_at }
POST /v1/unlock/claim   { "quote_id", "trans_id" } → { unlocked: true, episode_id } | { code: 40901 }
```

- `claim` 必须带一条 `CREDITED` 的 `trans_id`，服务端校验该 trans 未被别的 `quote_id` 用过（`UNIQUE(trans_id)`），**一次激励只能解锁一集**。
- 解锁状态落 `user_unlock` 表（`UNIQUE(user_id, episode_id)`），重装后从服务端恢复，不只靠本地存储。

## 7. 广告与奖励接口

### 7.1 `GET /v1/ad/decision?slot=rewarded&scene=episode_completed`

频控中心是唯一裁决者，客户端每次展示前必须问一次：

```json
{
  "code": 0,
  "data": {
    "allow": true,
    "slot": "rewarded",
    "ad_unit": "topon_br_rewarded_01",
    "reason": null,
    "quota": { "used": 4, "cap": 15, "remaining": 11, "reset_at": 1762905600000 },
    "min_interval_ok": true
  }
}
```

拒绝时 `allow=false` + `reason ∈ {DAILY_CAP, HARD_CAP, INTERVAL, COOLDOWN, DISABLED, NO_SESSION}`，并给 `retry_after_ms`。**客户端不得自行放宽**：本地只许「提前加载」，不许「提前展示」。

频控矩阵（唯一真值表）：

| 广告位 | 触发点 | 每日上限 | 最小间隔 | 新用户保护 |
|---|---|---|---|---|
| 激励视频 | 金币球 / 任务页 / 加速解锁 | 15 | 无（用户主动） | 首日同 15 |
| 插屏 | 每 2 集转场（仅上滑切集） | 12 | ≥2 集 | 首日 ≤4 |
| 开屏 | 回前台（后台 >30s） | 1 | 60s | 首次启动永不出 |
| 总量 | 派生 `reward+inter+appopen` | 默认 28 | — | 硬上限 40，命中后全关（含激励） |

### 7.2 `POST /v1/ad/impression`

客户端上报「真实展示」，关联策略与实验组；**收入以 TopOn 回调为准，客户端不报金额**：

```json
{ "slot": "rewarded", "ad_unit": "topon_br_rewarded_01", "impression_id": "imp_01H...", "network": "admob", "shown_at": 1762905000000, "strategy_id": "ad_reward_01", "strategy_version": 3, "experiment_id": "exp001", "variant": "B", "placement_id": "pl_br_rw_1" }
```

`UNIQUE(app_id, impression_id)` 去重；重复上报返回 200 + 首条结果。

TopOn 侧收入回调（服务端到服务端）写入 `ad_revenue`，必须保存：`revenue_raw` / `currency_raw` / `precision`（`estimated|confirmed`）/ `network` / `placement_id` / `impression_id` / `shown_at` / `fx_snapshot`。

### 7.3 `POST /v1/ad/s2s/reward`（可信回调，`OPEN-11`）

```
POST /v1/ad/s2s/reward
trans_id=<平台交易号>&user_id=<uid>&ad_unit=<unit>&ts=<秒>&sign=<HMAC>
```

| 契约 | 值 |
|---|---|
| 签名 | `HMAC-SHA256(trans_id + user_id + ts, secret)`，secret 仅服务端持有，90 天轮换 |
| 时间窗 | ±300s，超出视为重放拒绝 |
| 必带 | `trans_id` / `user_id` / `ad_unit` / `ts` / `sign`，缺一 400 不记账 |
| 幂等 | `UNIQUE(trans_id)`，重复回调 200 + 首笔结果，不重复发币 |
| 发放 | +50 moedas/次（与前置弹窗文案严格一致，不许动态改；日上限 15 条由 `/v1/ad/decision` 控） |
| 回查 | 3 次 1s/3s/10s，仍无结果 → `DENIED` 流水，**不预发不补发** |

> `trans_id` 是广告平台字段，具体参数名/签名方式以实际接入的 TopOn 版本为准 → `OPEN-11`。客户端**永远拿不到这个接口**，也不允许上传 `ad_completed=true` 换钱。

### 7.4 奖励报价与领取（弹窗内嵌奖励）

弹窗里的奖励（fixed / multiplier / bonus）走两段式，客户端只展示不决定金额：

```json
// GET /v1/reward/offer?popup_id=wheel&strategy_id=popup_double_01
{
  "code": 0,
  "data": {
    "offer_id": "offer10001",
    "reward_type": "multiplier",
    "multiplier": 2,
    "base_amount": 100,
    "target_total_amount": 200,
    "already_granted_amount": 100,
    "incremental_amount": 100,
    "display_amount": { "coins": 100, "amount": "R$ 0,01", "currency": "BRL" },
    "claim_condition": "watch_episode_completed",
    "currency_type": "IN_APP",
    "expires_at": 1762909200000
  }
}

// POST /v1/reward/claim  { "offer_id": "offer10001", "proof": { "type": "episode", "id": 2005 } }
{
  "code": 0,
  "data": { "reward_txn_id": "rt_01H...", "credited": 100, "balance": 3300, "status": "SETTLED" }
}
```

硬规则：

- **倍数奖励的增量公式**：`incremental = target_total − already_granted`，客户端若显示 2X 就必须是「总 200」，而账本只追加 100。四个字段必须都下发，让客户端能解释清楚。
- 领取时服务端重新校验：身份 / 资格 / `strategy_version` / 是否已领（`UNIQUE(offer_id)`）/ 是否过期 / 预算是否够 / 可信完成证明。
- 预算：`单用户次数` / `单次上限` / 日预算 / 活动总预算，超限只停「新资格」，已承诺的不得拒付。
- 现金奖励 (`currency_type=CASH`) 必须关联**已批准奖励来源**；`IN_APP` 为不可提现权益。两者分账，不混账。

**状态机（单向，无回退环）**

```
CREATED ──▶ REVIEWING ──▶ PROCESSING ──▶ PAID
   │            │              │
   │            └──▶ REJECTED  └──▶ FAILED
   └── 30min 未提交渠道 → 转 REVIEWING 并告警（不自动放行）
```

| 状态 | 用户可见 | 超时 | 允许操作 |
|---|---|---|---|
| CREATED | 已提交 | 30min | 无（不可取消） |
| REVIEWING | 审核中 | 15 / ~18 / ~24 / ~30 个工作日（按档位） | 联系客服 |
| PROCESSING | 打款中 | 1 个工作日 | 查看流水 |
| PAID | 已到账 | 终态 | 查看凭证 / 再提 |
| REJECTED | 未通过 | 终态 | 申诉 / 改资料重提 |
| FAILED | 打款失败 | 终态 | 换渠道重提 |

**拒绝原因码（5 个，文案与余额处理固定）**

| 码 | pt-BR 文案 | 触发 | 余额 |
|---|---|---|---|
| R01 | Titular do PIX diferente do CPF da conta | 姓名/CPF 与渠道不一致 | 退回，可改资料重提 |
| R02 | Revisão de segurança não concluída | 同设备多账号、心跳异常 | 退回，48h 内给结论 |
| R03 | Banco recusou o PIX | 渠道拒付 | 退回，建议换渠道 |
| R04 | Conta bloqueada para saque | 退款滥用 / 黑产 | 冻结，仅申诉可解 |
| R05 | Limite de saque atingido | >1 单/日 或 >$10/日 | 不冻结，次日可提 |

### 8.7 `GET /v1/withdraw/{id}/progress`（提现进度查询）

提现是全产品唯一的真钱出口，用户在这一页最焦虑。BF-06-14 要求：**预计到账日按工作日实时推算（`addBusinessDays`，跳过周末与巴西法定假日），并常驻显示「faltam N dias úteis」**。

```

```

```json
{ "code": 0, "data": {

  "status": "REVIEWING",

```

| 字段 | 说明 |
|---|---|
| `stages[]` | 四段固定：`CREATED → REVIEWING → PROCESSING → PAID`；`state ∈ done/current/pending/failed`，`REJECTED`/`FAILED` 时对应段变 `failed` 并终止 |
| `business_days_total` | 该档位的基础 SLA（15 / 18 / 24 / 30，按档位） |
| `business_days_saved` | 三通道累计减免，**硬上限 12** |
| `business_days_left` | `max(0, total − saved − 已过工作日)`，服务端算；客户端不自己减 |
| `eta_date` | `addBusinessDays(created_at, total − saved)` 的结果，`YYYY-MM-DD` |
| `accel.ad` | 激励加速：日上限 5 条、每条 −1 工作日；`enabled=false` 时 `reason` 给文案（额度用完/已达 12 天上限/订单已终态） |
| `accel.invite` | 邀请加速：每有效邀请 −3 个工作日、封顶 6 人（与 BF-08-02 同口径） |
| `accel.newbie` | 新人礼包一次性 −3 天（BF-01-04），用过后 `enabled=false` |
| `next_action` | 服务端告诉客户端「下一步该点哪个」：`watch_ad`（还能加速）/ `wait`（等就行）/ `fix_info`（资料问题）/ `appeal`（被拒可申诉）/ `none`（已到账） |

硬规则（写进验收）：

1. **加速只改 `eta_date` 与 `business_days_left`，不改订单金额、不改状态、不承诺具体到账时刻**（BF-06-14 原文：不承诺具体到账时刻）。
2. 三通道累计减免 **≤12 个工作日**；达到上限后 `accel.*.enabled=false`，`reason` 必须给具体原因，不给「不可用」三个字。
3. 状态已 `PAID` 时 `business_days_left=0`、`eta_text="concluído"`，加速入口全部隐藏（不允许给已完成订单加速）。
4. `REJECTED` 的订单不再显示 `eta_*`，改显示 `reason_code` + `reason_text` + 申诉入口。
5. 工作日计算**以服务端为准**，客户端不得本地算日期（时区与节假日表都会漂）。
6. 状态机单向：`CREATED→REVIEWING→PROCESSING→PAID`，任何回退请求直接拒绝并告警（见 8.9）。

**「看广告加速」的合规边界**：加速只是缩短**审核排队时间**，不改变提现金额，也不把提现资格绑到广告上——BF-06-14 与 5.11 禁止项①明确禁止「看广告插队提现」。产品上的表述必须是「adiantar a análise」（提前审核），不能说「pagar mais rápido」。

### 8.9 PIX 打款回调（服务端）


对应 PRD **BF-08 邀请与裂变**。核心口径（不要自行发挥）：

| 项 | 值 | 来源 |
|---|---|---|
| 邀请码 | **6 位**，服务端生成，终身不变；不用裸链接当码 | BF-08-01 |
| 绑定窗口 | 注册后 **24h 内**可绑，**绑定后不可更换** | BF-08-01 |
| 邀请人奖励 | **+2.000 moedas + 提现加速 3 个工作日**（加速封顶 6 人） | BF-08-02 / BF-06-14 |
| 被邀请人奖励 | **+1.000 moedas**，随新人礼包合并发放，**不单独再发一份** | BF-01-04 |
| 结算时点 | 被邀请人**完成首集有效观看**后结算邀请人奖励（不是绑定即发） | BF-08-02 |
| 月上限 | **20 次/月**（UI：Máx. 20 convites/mês） | BF-07-03 T_INV1 |

| 状态 | 两态：**待确认 PENDING / 已确认 CONFIRMED**，不预付 | BF-08-02 |
| 反刷 | 1 设备 1 账号；同设备新账号不计；1 个 CPF 1 个码 | BF-08-01 / 5.12 |

### 9.3 `POST /v1/invite/bind`（绑定邀请码）

```json
// req

// resp
{ "code": 0, "data": { "bound": true, "inviter_masked": "M*** S.", "reward_preview_coins": 1000, "bind_expires_at": null } }
```

校验顺序（任一失败即拒，不写入）：

| 顺序 | 校验 | 失败码 |
|---|---|---|
| 1 | 邀请码存在且属于**其他**用户 | `40420 INVITE_CODE_INVALID` / `42210 INVITE_SELF` |
| 2 | 本人注册时间 ≤24h，且从未绑定过 | `42211 INVITE_WINDOW_CLOSED` / `40930 ALREADY_BOUND` |
| 3 | 本设备未绑定过其他账号，且非「同设备新账号」 | `42212 INVITE_DEVICE_REUSED` |
| 4 | 邀请人本月名额未满（20） | `42213 INVITE_LIMIT_REACHED` |
| 5 | 双方 `risk_flag.level` 未命中 | `40320 INVITE_RISK_BLOCKED` |

- **绑定后不可解绑、不可换码**（BF-08-01）；重复调用返回 `40930` 并回带已绑定的邀请码掩码。
- `reward_preview_coins=1000` 是**被邀请人**那份（随新人礼包合并发放），不是邀请人的 2.000，不要显示错。
- 绑定成功**不发币**，只建立关系；发币在被邀请人完成首集有效观看时由服务端触发。
- 游客也可绑定（绑定关系挂 `device_id`，登录后随账号迁移），但 `is_guest=true` 时 `settled` 延后到登录后 —— 否则清缓存重装即可刷奖励。

**范围声明（重要）**：本期商品目录只服务**转盘抽中的实物兑付**，不是金币商城。

## 13. 策略决策与实验（平台层）

第一期客户端只依赖「配置 + 频控 + 弹窗决策」，完整的策略服务可作为第二阶段接入，接口形状先定下来。

### 13.1 `POST /v1/strategy/decide`

```json
// req
{ "app_id": "cinecoin_br", "scene": "episode_completed", "user_id": 1000123, "session_id": "s_01H", "event_id": "evt_01H", "context": { "episode_id": 2005, "series_id": 1001 }, "client_capabilities": ["popup_v1", "topon_interstitial", "topon_rewarded"] }

// resp
{ "code": 0, "data": {
  "decision_id": "dec_01H",
  "strategy_id": "ad_inter_01", "strategy_version": 3,
  "experiment": { "id": "exp001", "variant": "B", "bucket": 78 },
  "action": { "type": "ad", "slot": "interstitial", "ad_unit": "topon_br_inter_02", "display": { "min_interval_episodes": 2 } },
  "reward": null,
  "expires_at": 1762909200000
} }
```

约束：

- 每次最多返回**一个**需立即执行的动作；顺序弹窗靠 `flow` 续取。
- 服务端以已认证身份与权威状态为准，**不信任客户端上传的余额 / 观看总次数 / 提现状态**。
- `experiment.variant` 由服务端稳定哈希 `hash(app_id + experiment_id + user_id) % 100` 决定，客户端不得改；入组时间必须早于被测试业务动作。
- 后端失败：短剧照常播、不发未经确认的奖励、不放宽频控、不自行发起提现、必要时停营销弹窗、本地留非敏感事件补报。

### 13.2 实验上报 `GET /v1/experiments/{id}/summary`（后台用）

返回 `variant A/B` 的 `users`（含零曝光）、`impressions`、`impressions_per_user`、`ad_revenue`、`reward_cost`、`net_contribution`、`d1_retention`、`sample_warning`。主指标口径：**观察窗口内有效曝光总数 ÷ 已随机分组用户数（零曝光计入分母）**。

## 14. 管理后台接口

统一前缀 `/api/admin`，管理员会话 + RBAC + 审计日志（操作人、时间、旧值→新值、工单号）。

| 分组 | 接口 | 说明 |
|---|---|---|
| 广告策略 | `GET/POST/PUT /strategies/ad`、`POST /strategies/ad/{id}/pause`、`POST /strategies/ad/{id}/rollback` | 列表字段：名称/触发场景/用户类型/广告类型/频次/状态 |
| 弹窗策略 | `GET/POST/PUT /strategies/popup` | 编辑时**内嵌奖励配置**，不跳独立奖励页 |
| 配置参数 | `GET/PUT /configs/ad`、`GET /configs/audit` | 整包校验失败返回冲突项；24h 内只允许改 1 个参数 |
| 发布 | `POST /releases`、`POST /releases/{id}/rollback`、`POST /releases/{id}/pause` | 版本单调递增，历史不覆盖；紧急暂停立即阻止新决策 |
| AB Test | `GET/POST /experiments`、`POST /experiments/{id}/start`、`/stop`、`/promote` | 复制策略生成 B 组，流量比例，指标对比 |
| 看板 | `GET /dashboard/overview`、`GET /dashboard/strategies`、`GET /dashboard/experiments` | 筛选：app/日期/GEO/用户类型/广告类型/策略/实验 |
| 审计 | `GET /audit/logs` | 谁在什么时候改了什么 |

运营体验硬要求：常见策略用默认参数即可创建；改奖励倍数**不必**换模板；已发布策略用新版本修改；支持紧急暂停与一键回滚；普通参数改动**不需要客户端发版**。
