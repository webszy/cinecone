## 4. 关键还原点

- **余额滚动**：1.2s ease-out，串行队列，多笔并发不叠加；rAF 不可用时到点强制收敛（后台标签也不会卡住）
- **进度条 5.16 分段缓动**：A 面按 PRD 三段系数（前段 ÷1,6、中段线性、末段 ×1,2 收到 1），B 面用更接近线性的另一条曲线；两面都**达标瞬间强制 100%**（红线 14「进度不说谎」），且余额冲正时先停 3s 再回落一次
- **弹窗唯一真值表**：8 个弹窗的触发条件、频次、冷却全部收在 5.14，原型里每个弹窗都有独立开关与冷却状态
- **转盘**：30s 冷却、每会话 3 次、加权概率 `26/24/16/10/12/8/4/1`，飘字 + 通知底栏
- **卸载挽留**：只挽留不拦截；「一步到系统卸载」始终可见；7 天冷却文案
- **区域配置 5.15**：BR = PIX / R$，MX = SPEI / MX$，提现方式、CTA、hint、流水符号、表单标题全部跟随

## 5.5 真实数据接入（v1.2）

接口文档：`~/Downloads/short-drama-api (1)/短剧 App 接口接入说明.md`，基础地址 `https://api.salesmarto.com/app-api/drama`，全部 GET、无需鉴权。

| 用途 | 接口 | 原型里对应 |
|---|---|---|
| 首页内容 | `/home` | 分类 chip、推荐位数据源 |
| 分类 | `/categories` | Dramas 顶部 chip（按剧目数取前 9） |
| 剧目列表 | `/dramas` | Dramas 网格分页（101 部） |
| 剧目详情 | `/dramas/{id}` | 详情页标题 / 简介 / 集数 |
| 分集 | `/dramas/{id}/episodes` | 选集网格的 free / locked 状态 |
| 首页视频流 | `/home-feed` | Feed 竖屏（取前 8 条，真实 mp4） |

**取数链路**（`src/35-data.js`）：

1. `#cc-snap`（构建时注入的 `data/snapshot.json`）同步解析，立即可用；
2. `CCData.reload()` 启动后尝试 `fetch` 实时数据，成功则替换并回调 `window.CCHydrate()` 整体重绘；
3. 实时失败（含 CORS）静默保留快照；快照缺失才退回 `40-app.js` 的演示数据。

字段映射：`id → 'r'+id`、`categoryCodes → cats[]`（`cat` 取首个）、`totalEpisodes → eps`、`freeEpisodeCount → free`、`heatText → views`、`coverUrl → cover`；`home-feed.items[].videoUrl` 直接作为 `<video src>`，封面作为 poster + 兜底图。

**刷新快照**（接口内容更新后重跑，然后重新构建）：

```bash
curl -s "$B/home?countryCode=BR&locale=pt-BR"     -o /tmp/home.json
curl -s "$B/dramas?countryCode=BR&locale=pt-BR"   -o /tmp/dramas.json
curl -s "$B/home-feed?countryCode=BR&locale=pt-BR" -o /tmp/feed.json
python3 tools/snapshot.py      # 合并成 data/snapshot.json
python3 build.py               # 重新内嵌
```

> 服务端目前**未返回 `Access-Control-Allow-Origin`**，浏览器直接请求会被 CORS 拦。要让「实时模式」生效，需要服务端加该响应头，或在同源网关上反代 `/app-api`（前端把 `BASE` 指向相对路径即可）。

新增调试参数：`#detail`（直达首条剧详情）、`#search`（直达搜索页）、`#nopromise`（跳过首开承诺弹窗，便于截图）。

## 5.7 解锁播放与提现页 A/B（v1.4）

### 5.7.1 为什么之前「解锁了还是看不了」

接口的分集列表**只给元数据**（`episodeNo / duration / free / locked`），播放地址只出现在 `/home-feed` 的条目里。所以一集能不能播，要按三级取源：

| 级别 | 命中条件 | `kind` | 界面 |
|---|---|---|---|
| 1 | `/home-feed` 里正好有这剧的这集 | `exact` | 这集的原片 |
| 2 | 有这剧的其它集 | `drama` | 同剧片段（画面是这部剧） |
| 3 | 这剧完全不在视频流里（101 部里 89 部如此） | `demo` | 全局第一条演示片段，**控制台「播放源」会标出来** |
| — | 一条视频都没有（离线 + 无快照） | `none` | 停在剪影 + 封面，不假装播放 |

解锁链路：`点锁定集 → 前置弹窗（文案变成"Desbloquear EP xx"）→ 看完 → markUnlocked（写 localStorage，幂等）→ 到账弹窗 → 关闭后自动 playEpisode(id, ep)`。

`playEpisode` 做四件事：该剧已有屏就复用、没有就插一屏（插在当前屏之后）；`<video src>` 换成这集的源；集号 / 标题 / 时长同步；从头开播。自测与 CDP 都验证过 `readyState=4 / paused=false / currentTime` 在走。

### 5.7.2 提现页多套（BF-11-04）

```
bucket = fnv1a(device_id + "|wd_page_v1") % 100
page_id = bucket < 50 ? "wp_br_a" : "wp_br_b"
```

同一设备 30 天内不换桶（`cc_wd_bucket_v1` 落盘，带 `at` 时间戳），客户端不本地随机。原型没有服务端，用同一套哈希在本地算一次来模拟「下发」，控制台「分桶」一栏显示 `bucket 78 · wp_br_b`，切 A/B 只是临时覆盖、刷新回到真实桶。

| 维度 | A 面 | B 面 |
|---|---|---|
| 区块顺序 | 余额 → 方式 → 档位 → CTA | 余额 → 档位 → 方式 → CTA |
| 档位排布 | 2×2 竖排网格 | 横向滑动，右侧露出下一张（`scroll-snap`） |
| 余额卡插画 | 有 | 无 |
| 进度条系数 | PRD 5.16 三段 | 接近线性、前段略压 |
| 提示语顺序 | 先步骤后时效 | 先差额与集数，再时效 |
| 主按钮 | `Sacar · R$ 5,00 via PIX` | `Continuar` / `Continuar · R$ 5,00 via PIX` |

**逐字一致的部分**（PRD 红线，自测逐项比对）：余额、US$ 折算、四档金额、手续费文案、SLA 文案。这些都由 `renderWallet()` 统一生成，两面只是拼接顺序不同，所以「两面 diff = 0」是可以被机器验的，不是靠肉眼。

## 6. 已知限制（刻意不做的）

- 没有真实广告 SDK、没有后端、没有支付；所有金额变化都在内存里，刷新即重置（可用「重置数据」手动归零）
- **接口未开 CORS**：`api.salesmarto.com` 的响应没有 `Access-Control-Allow-Origin`，浏览器直接 `fetch` 会被拦。因此构建时把三个接口的真实返回存成快照内嵌（`data/snapshot.json`），运行时先试实时拉取，失败静默回退快照。控制台「数据」一栏可见当前来源（`snapshot da API` / `API ao vivo` / `demo`）
- 分集 `videoUrl` 为真实 mp4（muted 自动播放）；网络不可达时回退到同名封面 + CSS 剪影，不会出现破图。**`/home-feed` 只覆盖 12 部剧**，其余剧的集用的是同一段演示片段（控制台「播放源」标为「演示片段」），这是接口能力的边界，不是播放逻辑缺失
- 提现页 A/B 的「服务端下发」用本地哈希模拟：真实 App 里 page_id 由服务端返回，客户端只负责渲染
- 激励视频演示时长 5s（代码里 `AD_TOTAL`，正式 30s），角标读同一常量
- 音效需用户首次点击后才会初始化（浏览器 autoplay 策略）

## 5.8 金币经济与提现加速（v1.5 定框架 / v1.6 定币制）

**金币唯一资产**（v1.6 拍板的口径）：

| 层 | 单位 | 说明 |
|---|---|---|
| 资产层 | moedas（唯一记账单位） | 看剧 100/集、签到 100~800、每日任务 150~2.000、邀请 2.000、转盘 100~1.500；界面一律只显示 moedas |
| 换算层 | 1.000 moedas = R$ 1,00 | **只在提现页出现**：余额卡显示金币 + "= R$ x,xx · ≈ US$ y,yy"；档位显示 R$ 值 + 金币等价；流水收入用金币、提现记录用 R$ |

实现要点：`COIN_RATE = 1000`；`state.coins` 是唯一真值，`state.bal` 只是派生值（coins / 1000），保证金币与现金永不打架；`paintBal()` 是所有余额 DOM 的唯一写入口。

**任务中心（中间 Tab）**：7 天签到（翻倍 / 补签都要看广告，受每日 15 条激励上限约束）→ 每日任务 5 条（看 3 集 / 看 5 广告 / 分享 / 签到 / 邀请）→ 邀请卡 → 广告上限卡。

**领金币的翻倍分支**：看剧累积进待领池，点击弹「领金币」——`adsToday < adCap` 时给「看广告 ×2」，达上限后翻倍按钮隐藏、只能直领（自测有正反两条）。

**激励打满 → 转盘**：`adsToday >= 15` 后上限卡亮出「Abrir roleta」，且下次广告看完自动弹转盘；转盘先扣 500 moedas 再转，8 格加权（金币 100~1.500 / 实物礼品，礼品弹确认层），期望返还约 75%。

**提现加速（15 个工作日）**：提交后独立计期；看广告 -1 天（日上限 5）、邀请好友 -3 天/人（封顶 6）、新人礼包一次性 -3 天；预计到账日按工作日推算（`addBusinessDays`）。加速面板在提现状态页，含剩余天数、进度条、两个加速入口。

**新人链路**：冷启 splash → 新人礼包（1.500 moedas + 3 天加速）→ 首开承诺（20.000 moedas 待返）→ 首页；`#nonewbie` / `#nopromise` 可分别跳过。**v1.8 看剧页**：新增独立全屏播放页 `data-page="player"`——详情页点某一集 / `#dtPlay` / 锁集解锁后都进这里整集播放，看剧计币、金币收集球、领金币翻倍、切上下集、播完自动下一集全部在本页完成，不再跳回首页信息流；返回回到来源页（详情页）。计币池与首页共用（两个收集球同一池）。首页信息流保留刷剧浏览，播放页打开时信息流自动停播。调试 `#player` 直达。**v1.7.4 画面改版**：① 视频不再任何自动缩放（kenburns 全删 + 全视频层 `animation:none` 兜底）；② **横屏/方形素材不再被 cover 放大裁切**——`loadedmetadata` 实测比例，比容器宽 >1.35 倍切 `contain` 完整显示，上下用同帧封面做模糊填充（`is-wide` 类）；竖屏素材仍满屏。**v1.7.2 计币改版**：看剧金币从 0 起算、播放进度每 1% 涨 1 moeda（≈42s/集）、满 100 封顶停住，收集球灰→金、角标数字实时跳动；满 100 才能点收集球手动领取（未满 toast 还差 N 个），领取后归零重新涨；滑走/切集本集进度作废，绝不自动入账。**v1.7.1 领取改版**：主按钮 = 「Ver anúncio e dobrar · +3.000」（看 1 条激励把金币翻倍，走 `playAd('newbiedouble')`）；次按钮 = 直接领取 +1.500；小字「Agora não」跳过。当日激励额度打满时翻倍按钮隐藏、直领升为主按钮（不留死按钮）；3 天提现加速无论哪条路径都随礼包发放。
